# 社区慢病随访用药提醒与家庭血压平台

面向城市社区的慢病（高血压 / 糖尿病 / 冠心病）一体化管理平台：社区医生建档与分层管理，居民/家属上传家庭血压、血糖、用药、饮食、运动数据，平台自动判断是否达标，异常时把任务推送给社区护士、医生和家属；随访、转诊、住院、失访等关键事件全部回流到同一份慢病档案。

技术栈：**React 18 + Vite（前端） · Spring Boot 3 + Spring Data JPA（后端） · PostgreSQL 16（数据库） · Nginx（前端托管与反向代理）**，全部容器化，一键 `docker compose up -d` 启动。

---

## 原始需求

> 建设城市社区慢病随访用药提醒与家庭血压平台，可采用 React、Spring Boot 和 PostgreSQL。社区医生为高血压、糖尿病或冠心病居民建立档案，记录诊断、药物、目标血压、并发症、家属联系人、医保签约和随访计划。居民或家属上传家庭血压、血糖、用药、饮食和运动记录后，平台判断是否达标。若连续漏服、血压异常升高、低血糖、药物不良反应或居民长期不上传，平台会把任务推给社区护士、医生和家属。随访时，医生查看趋势、用药依从性、家属反馈和近期就医，再决定调整提醒、建议复诊或转诊上级医院。药物变更、家属代管、住院、失访和转诊结果都要回到同一慢病档案，帮助社区判断哪些居民需要重点管理。社区医生还要按家庭支持程度分层管理，判断哪些居民需要家属代管、上门随访或转入重点慢病名单。失访居民会进入重点名单。医生端会显示每次家属代管和居民自测的差异。平台还要把家庭血压数据、用药提醒和线下随访纳入同一慢病计划，社区医生能判断异常来自疾病变化、用药依从性还是家属照护缺口。

## 快速启动（Docker 一键部署）

前置条件：已安装 Docker 与 Docker Compose。

```bash
cp .env.example .env        # 可选，不改也能直接用默认值启动
docker compose up -d --build
```

启动后访问：**http://localhost:8080**（端口由 `.env` 中 `CC_PUBLISH_PORT` 决定，默认 8080）。

- 前端 nginx 托管 React 静态资源，并把 `/api/**` 反向代理到后端；
- 后端、数据库均不直接向宿主暴露端口（数据库仅在 compose 内部网络）；
- 首次启动自动写入演示账号与 30 天演示数据（设 `SEED_DEMO_DATA=false` 可关闭）。

停止并释放资源：

```bash
docker compose down            # 保留数据卷
docker compose down -v         # 连同数据库数据一起清除
```

### 验证方式（宿主 docker compose up）

本项目的验证标准为：在宿主机执行 `docker compose up -d --build` 后，

1. 三个容器（db / backend / frontend）全部 healthy 或 running；
2. 浏览器打开 `http://localhost:<CC_PUBLISH_PORT>` 能登录并走通关键业务流；
3. 接口健康检查：`curl http://localhost:<CC_PUBLISH_PORT>/api/health` 返回 `{"status":"UP"}`。

## 演示数据与关键业务流

首次启动自动初始化 4 份慢病档案与 30 天家庭监测数据，可直接体验：

1. **达标判断与告警**：张福生（resident）近 3 天血压连续超标 → 自动生成「血压异常」告警；近 3 天漏服 3 次 → 生成「连续漏服」告警；刘桂芳一次 3.5 mmol/L 血糖 → 「低血糖」紧急告警；陈国强上报服药后胃部不适 → 「药物不良反应」告警。
2. **失访与重点名单**：赵永贵（resident4）超 14 天未上传 → 系统自动标记失访、转入重点慢病名单并生成紧急告警（定时巡检每小时执行，规则常量见 `RuleEngine`）。
3. **家属代管差异**：张福生的血压部分由儿子张小明代测，医生端「趋势与依从性」页分两条曲线展示**居民自测 vs 家属代测**并给出均值差异。
4. **统一慢病计划**：每份档案包含家庭监测数据 + 用药提醒（居民端今日打卡）+ 线下随访计划，随访录入后自动更新下次随访日期。
5. **事件回流**：药物变更、家属代管设置、住院、失访、转诊及转诊结果回填、分层调整，全部写入档案「事件流」页签。
6. **分层管理**：档案详情页顶部展示系统分层建议（依据家庭支持程度、近 30 天依从性、告警频率、是否代管），医生可一键采纳，调整为家属代管 / 上门随访 / 重点名单。

### 推荐体验路径

1. `doctor/doctor123` 登录 → 工作台看待办告警与到期随访 → 进入「张福生」档案 → 趋势页看自测/代测差异与依从性 → 录入一次随访（处置选「调整提醒」）→ 事件流确认回流；

4. `nurse/nurse123` 登录 → 告警任务中心对告警「知晓 / 办结」。

## 核心规则（后端 `RuleEngine`）

| 规则 | 阈值 | 告警级别 | 推送对象 |
|---|---|---|---|
| 血压严重升高 | 收缩压 ≥180 或 舒张压 ≥110 mmHg | 紧急 | 医生/护士/家属 |
| 连续血压超标 | 连续 3 次超过档案目标值 | 警告 | 医生/护士/家属 |
| 低血糖 | 血糖 < 3.9 mmol/L | 紧急 | 医生/护士/家属 |
| 连续漏服 | 近 3 天漏服 ≥3 次 | 警告 | 医生/护士/家属 |
| 药物不良反应 | 上报即触发 | 紧急 | 医生/护士/家属 |
| 长期未上传 | >7 天提醒；>14 天判定失访并转入重点名单 | 警告/紧急 | 医生/护士/家属 |

同类未处理告警不重复创建，避免刷屏。分层建议综合：家庭支持程度（强/中/弱）、近 30 天用药依从性、上传频次、告警次数、是否有家属代管。

## 连续高血压预警（补充 → 电话确认 → 医生处置）

居民连续 3 次上传超标血压（或单次达危急值 ≥180/110）时，平台自动生成**连续高血压预警**并同步生成**电话随访任务**（随访计划自动提前到次日）：

1. **补充测量信息**：居民或家属在平台补充测量时间、是否服药、症状、是否就医；
2. **护士电话确认**：护士在告警任务中心看到待确认预警，电话确认并记录症状和用药情况；
3. **医生处置**：医生结合血压趋势、用药依从性和家属反馈，选择「调整随访提醒频次 / 建议门诊 / 联系家属」；调整频次时页面展示近 30 天超标统计、按时服药率与最近家属反馈作为依据，新间隔天数写回随访计划。

预警全流程（触发、补充、电话确认、处置）均写入档案事件流；医生工作台展示待处置预警，居民/家属端展示待补充预警。

## 异常归因（疾病变化 / 用药依从性 / 家属照护缺口）

档案详情接口与医生端详情页提供「异常原因判断」面板，基于近 30 天家庭监测数据给出三类结论，每条结论附可核验依据（具体次数、比率、告警条数）：

- **疾病变化**：在按时服药率 ≥80%（可排除漏服因素）的前提下，血压仍连续超标 ≥3 次、出现危急值或低血糖时检出；依据含超标次数/目标值、危急值次数、低血糖次数、同期依从性。
- **用药依从性**：近 30 天用药打卡 ≥3 次且按时服药率 <80% 时检出；依据含已服/漏服次数、按时服药率、连续漏服告警条数。
- **家属照护缺口**：家庭支持非「强」且未设代管、近 30 天上传 <8 次、存在长期未上传告警、或代管家属从未代测，任一满足即检出；依据含家庭支持程度、代管状态、上传/代测次数、未上传告警条数。

演示数据覆盖三类典型：张福生（漏服多 → 依从性）、刘桂芳（依从性好但低血糖 → 疾病变化）、陈国强（独居无代管 → 照护缺口）。

## 安全与工程说明

- 密码使用 BCrypt 加密存储；接口基于 Bearer Token（数据库令牌，7 天有效）认证；
- 后端按角色鉴权：医生仅见本人负责档案，家属仅见被关联档案，居民仅见本人档案；
- 前后端镜像均为多阶段构建、非 root 运行，并配置 HEALTHCHECK；
- 数据库不暴露宿主端口；演示数据仅在数据库为空时写入一次。
